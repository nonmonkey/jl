# MySQL 字符集与排序规则

## 一、字符集（Character Set）

字符集 = 数据库能存哪些文字、用什么编码存。

- `utf8mb4`：目前最推荐的字符集
  - 支持全世界几乎所有文字（中文、英文、emoji 等）
  - 1 个字符最多占 4 字节
  - MySQL 8.0 默认就是它

### 为什么不用 utf8？

MySQL 里的 `utf8` 是个坑：

| 名字 | 实际能存 | 能存 emoji 吗 |
|------|----------|---------------|
| utf8 | 最多 3 字节 | 不能 |
| utf8mb4 | 最多 4 字节 | 能 |

> MySQL 的 `utf8` 其实是"残缺版 UTF-8"，存 emoji 会报错。所以现在一律用 `utf8mb4`。

---

## 二、排序规则（Collation）

排序规则 = 在比较和排序时，怎么判断字符的大小和相等。

比如：
- A 和 a 算不算相等？
- 中文按拼音排还是按笔画排？

`utf8mb4_general_ci` 的含义：

- `utf8mb4`：对应字符集
- `general`：通用规则
- `ci`：case insensitive，不区分大小写（A = a）

---

## 三、常用字符集对比

| 字符集 | 说明 | 推荐度 |
|--------|------|--------|
| utf8mb4 | 完整 UTF-8，支持 emoji | 首选 |
| utf8 | 残缺版，不支持 emoji | 别用 |
| latin1 | 西欧字符，不支持中文 | 别用 |
| gbk | 中文编码，老系统用 | 特定场景用 |

---

## 四、常用排序规则对比

| 排序规则 | 特点 | 推荐度 |
|----------|------|--------|
| utf8mb4_general_ci | 不区分大小写，速度快，通用 | 常用 |
| utf8mb4_unicode_ci | 不区分大小写，排序更准确（支持多语言） | 更推荐 |
| utf8mb4_bin | 区分大小写，按二进制比较 | 特殊场景 |
| utf8mb4_0900_ai_ci | MySQL 8.0 默认，更现代 | 推荐 |

### ci 和 bin 的区别

```sql
-- ci（不区分大小写）
WHERE name = 'tom'   -- 能匹配到 'Tom'、'TOM'

-- bin（区分大小写）
WHERE name = 'tom'   -- 只能匹配到 'tom'

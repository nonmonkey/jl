# 模块 10 —— 索引（Index）

> SQL 里提升查询速度的核心手段，也是面试常问的点。
> 前置：前面所有模块。

---

## 一、什么是索引？

**索引 = 书的目录。**

- 没有目录，找内容要从第一页翻到最后一页（**全表扫描**）
- 有目录，直接翻到对应页码（**索引查找**）

数据库也一样：

- 没索引 → 一行行找，慢
- 有索引 → 直接定位，快

---

## 二、为什么需要索引？

假设 students 表有 100 万行：

```sql
SELECT * FROM students WHERE name = '张三';
```

- **没索引**：逐行扫描 100 万行，慢
- **有索引**：直接定位到"张三"，快

数据量越大，索引效果越明显。

---

## 三、索引的代价

索引不是白来的，有代价：

| 代价 | 说明 |
|------|------|
| 占空间 | 索引本身要存 |
| 降低写入速度 | 增删改时，索引也要跟着更新 |
| 维护成本 | 索引太多，反而拖慢整体性能 |

> 💡 **原则：查询频繁的字段建索引，写入频繁的少建。**

---

## 四、创建索引

### 1. 建表时创建

```sql
CREATE TABLE IF NOT EXISTS students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    INDEX idx_name (name)
);
```

### 2. 建表后创建

```sql
CREATE INDEX idx_name ON students(name);
```

### 3. 唯一索引

```sql
CREATE UNIQUE INDEX idx_email ON students(email);
```

唯一索引要求值不能重复（和建表时的 `UNIQUE` 约束效果一样，详见 `01.建库建表.md`）。

### 4. 复合索引（多列）

```sql
CREATE INDEX idx_name_age ON students(name, age);
```

---

## 五、查看索引

```sql
SHOW INDEX FROM students;
```

或者：

```sql
SHOW KEYS FROM students;
```

两个效果完全一样，`SHOW KEYS` 是 `SHOW INDEX` 的别名。

---

## 六、删除索引

```sql
DROP INDEX idx_name ON students;
```

---

## 七、索引的类型

| 类型 | 说明 | 例子 |
|------|------|------|
| 主键索引 | 主键自带 | `PRIMARY KEY` |
| 唯一索引 | 值不能重复 | `UNIQUE INDEX` |
| 普通索引 | 最常用 | `INDEX` |
| 复合索引 | 多列组合 | `INDEX(a, b)` |
| 全文索引 | 文本搜索 | `FULLTEXT` |

---

## 八、什么时候用索引？

### 适合建索引

- `WHERE` 频繁用的字段：`WHERE name = ?`
- `JOIN` 关联的字段：`ON a.id = b.a_id`
- `ORDER BY` 的字段：`ORDER BY score`
- `GROUP BY` 的字段

### 不适合建索引

- 数据量小的表（几百行，没必要，全表扫描也很快）
- 频繁增删改的字段（每次写入都要维护索引，成本高）
- 值重复率高的字段（比如性别只有男/女，索引区分度太低，用不上）

> 💡 判断标准是**区分度**（不同值的比例）。区分度高（姓名、邮箱）适合建；区分度低（性别、是否删除）建了也白建。

## 九、复合索引（多列索引）

### 1. 是什么

把多个字段**合起来建一个索引**，一次索引同时管好几列：

```sql
CREATE INDEX idx_name_age ON students(name, age);
```

相当于建了一本"先按 name 排、name 相同的再按 age 排"的目录。

### 2. 有什么用

**查询里经常同时出现多个条件时，一个索引就够用了：**

```sql
-- name 和 age 一起查，一个复合索引全搞定
WHERE name = '张三' AND age = 18
```

如果拆成两个单列索引，MySQL 一次查询一般只能选**一个**索引走，另一个条件还得"过滤"一遍。复合索引直接合并处理，更快，还省一份索引的维护成本。

| | 复合索引 (name, age) | 两个单列索引 name + age |
|---|---|---|
| 查 `name` | ✅ | ✅ |
| 查 `age` | ❌ | ✅ |
| 查 `name AND age` | ✅ 一个索引搞定 | 一般只走一个，另一个过滤 |
| 占空间 / 维护成本 | 一份 | 两份 |

> 💡 怎么选：两个字段**经常一起查** → 复合索引（又省又快）；其中某字段**也经常单独查** → 再单独给它建一个索引。

### 3. 最左前缀原则

```sql
CREATE INDEX idx_name_age ON students(name, age);
```

这个索引能加速：

| 查询 | 能用上索引吗 |
|------|--------------|
| `WHERE name = ?` | ✅ |
| `WHERE name = ? AND age = ?` | ✅ |
| `WHERE age = ?` | ❌（跳过了 name，用不上） |

**规则：复合索引从左往右用，不能跳过左边的列。**

为什么？目录是**先按 name 排**的，age 只在"同 name 内部"才有序。单独拿 age 查，目录整体并不是按 age 排的，没法直接定位。

类比：电话簿先按"姓"排、再按"名"排。你知道"姓+名"能直接查，只知道"名"却查不了——因为没按"名"单独排过序。

## 十、用 EXPLAIN 分析查询

```sql
EXPLAIN SELECT * FROM students WHERE name = '张三';
```

`EXPLAIN` = 让 MySQL 告诉你这条 SQL **打算怎么执行**（预览执行计划，不会真的执行）。重点看这几列：

| 列 | 含义 |
|----|------|
| `type` | 访问类型：`ALL` 是全表扫描（差），`ref` / `const` 好 |
| `key` | 实际用的索引（显示 `NULL` 表示没用索引） |
| `rows` | 预估扫描的行数，越少越好 |

`type` 常见值：

```
ALL   → 没走索引，全表扫描（要优化）
ref   → 走了索引（好）
const → 主键/唯一索引精确匹配（最好）
```

> 💡 写完带 `WHERE` / `JOIN` / `ORDER BY` 的 SQL，养成习惯先 `EXPLAIN` 看一眼 `type`，是 `ALL` 就考虑加索引。

## 十一、索引失效的常见情况

| 情况 | 例子 | 为什么失效 |
|------|------|-----------|
| 用函数包住字段 | `WHERE YEAR(birthday) = 2006` | 字段被函数处理，索引按原值排的，用不上 |
| 隐式类型转换 | `WHERE id = '1'`（id 是 int） | 类型不匹配，MySQL 转换后索引失效 |
| `LIKE` 以 `%` 开头 | `WHERE name LIKE '%张'` | 前缀未知，没法从索引开头开始定位 |
| `OR` 连接非索引列 | `WHERE a = 1 OR b = 2`（b 没索引） | 有一边没索引，整体放弃 |
| 复合索引跳过左列 | `WHERE age = 18`（索引是 name, age） | 违反最左前缀 |

### 怎么修？

```sql
-- ❌ 索引失效：函数包住字段
WHERE YEAR(birthday) = 2006

-- ✅ 改成范围查询，索引能用
WHERE birthday >= '2006-01-01' AND birthday < '2007-01-01'

-- ❌ 隐式转换（id 是 int，却给了字符串）
WHERE id = '1'

-- ✅ 类型一致
WHERE id = 1

-- ❌ 前缀模糊
WHERE name LIKE '%张'

-- ✅ 前缀确定（能用索引）
WHERE name LIKE '张%'
```

## 十二、练习任务

1. 给 students 表的 name 字段建索引
2. 查看索引：`SHOW INDEX FROM students;`
3. 用 `EXPLAIN` 分析 `WHERE name = '张三'`
4. 给 score 字段建索引
5. 删除 score 的索引
6. 建复合索引 `(gender, age)`，测试 `WHERE gender = '男'` 和 `WHERE age = 18`

参考：

```sql
-- 1.
CREATE INDEX idx_name ON students(name);

-- 2.
SHOW INDEX FROM students;   -- 能看到 idx_name

-- 3.
EXPLAIN SELECT * FROM students WHERE name = '张三';
-- key 列显示 idx_name，type = ref，说明走了索引

-- 4.
CREATE INDEX idx_score ON students(score);

-- 5.
DROP INDEX idx_score ON students;

-- 6.
CREATE INDEX idx_gender_age ON students(gender, age);

EXPLAIN SELECT * FROM students WHERE gender = '男';
-- ✅ 走了 idx_gender_age（最左前缀是 gender）

EXPLAIN SELECT * FROM students WHERE age = 18;
-- ❌ 没走 idx_gender_age（跳过了 gender，最左前缀失效）
```

## 十三、本节总结

- 索引 = 书的目录，加快查询
- 创建：`CREATE INDEX idx_name ON 表(字段);`
- 查看：`SHOW INDEX FROM 表;`
- 删除：`DROP INDEX idx_name ON 表;`
- 原则：**查询频繁的字段建，写入频繁的少建**；区分度低的别建
- 复合索引遵守**最左前缀**：从左往右，不能跳过左边的列
- 写完 SQL 用 `EXPLAIN` 看 `type`，是 `ALL` 就该考虑优化
- 别让字段被函数包、别隐式类型转换、`LIKE` 别以 `%` 开头——这是索引失效最常见的三种原因

# 模块 8 —— 事务（Transaction）

> SQL 里保证数据安全的核心机制，工作中非常重要。
> 前置：前面所有模块。

---

## 一、什么是事务？

**事务 = 一组要么全部成功、要么全部失败的操作。**

经典例子：转账

A 给 B 转 100 元，需要两步：

1. A 的账户 -100
2. B 的账户 +100

这两步必须**同时成功**。如果第 1 步成功、第 2 步失败，钱就凭空消失了。

事务就是保证：**要么两步都成功，要么两步都不做。**

---

## 二、事务的 4 个特性（ACID）

| 特性 | 含义 |
|------|------|
| A 原子性 | 要么全做，要么全不做 |
| C 一致性 | 数据从一种正确状态变到另一种正确状态 |
| I 隔离性 | 多个事务互不干扰 |
| D 持久性 | 提交后永久保存 |

> 💡 小白先记住**原子性**就够了。

---

## 三、事务的三个核心命令

| 命令 | 作用 |
|------|------|
| `START TRANSACTION` | 开始事务 |
| `COMMIT` | 提交（确认所有操作） |
| `ROLLBACK` | 回滚（撤销所有操作） |

---

## 四、基本用法

```sql
START TRANSACTION;

UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;

COMMIT;
```

- 两步都成功 → `COMMIT` 提交
- 中间出错 → `ROLLBACK` 撤销

---

## 五、完整例子：转账

先建表：

```sql
CREATE TABLE IF NOT EXISTS account (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    balance DECIMAL(10,2)
);

INSERT INTO account VALUES
(1, '张三', 1000.00),
(2, '李四', 500.00);
```

转账 100：

```sql
START TRANSACTION;

UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;

-- 查看结果
SELECT * FROM account;

-- 确认无误，提交
COMMIT;
```

如果发现问题，回滚：

```sql
ROLLBACK;
```

回滚后，数据回到事务开始前的状态。

> 💡 `SELECT` 在事务里执行**不需要提交**，它是"看一眼"，不改数据。

---

## 六、事务的两种结局

### 1. 提交（COMMIT）

```sql
START TRANSACTION;
UPDATE ...;
UPDATE ...;
COMMIT;      -- 确认，永久生效
```

### 2. 回滚（ROLLBACK）

```sql
START TRANSACTION;
UPDATE ...;
UPDATE ...;
ROLLBACK;    -- 撤销，回到开始前
```

---

## 七、自动提交（AUTOCOMMIT）

MySQL 默认是自动提交的：

- 你写一条 UPDATE，不写 `START TRANSACTION`，它**立即生效**
- 一旦执行 `START TRANSACTION`，就进入手动模式，直到 `COMMIT` 或 `ROLLBACK`

查看当前模式：

```sql
SELECT @@autocommit;   -- 1 = 自动提交，0 = 手动
```

关闭自动提交：

```sql
SET autocommit = 0;
```

开启自动提交：

```sql
SET autocommit = 1;
```

> 💡 实际开发中一般**保持自动提交**（默认），需要事务时显式 `START TRANSACTION`，用完就结束。

---

## 八、事务的典型场景

| 场景 | 为什么用事务 |
|------|--------------|
| 转账 | 扣钱和加钱必须同时成功 |
| 下单 | 扣库存和生成订单必须同时成功 |
| 批量插入 | 一批数据要么全进，要么全不进 |
| 删除关联数据 | 删主表同时删子表，保证一致 |

---

## 九、常见错误

| 错误 | 原因 |
|------|------|
| 数据没真正保存 | 忘记 `COMMIT` |
| 出错后数据没撤销 | 忘记 `ROLLBACK`（或者已经 `COMMIT` 了，撤不回了） |
| 事务太长 | 锁住太多行，影响性能，事务里别放无意义的等待/长查询 |
| DDL 回滚不生效 | `CREATE TABLE` / `DROP TABLE` 等 DDL **不能回滚** |

> ⚠️ MySQL 里 DDL（建表、删表、改结构）一执行就生效，`ROLLBACK` 撤不掉。只有 DML（`INSERT` / `UPDATE` / `DELETE`）在事务里可回滚。

## 十、练习任务

1. 建 account 表，插入两条数据
2. 用事务实现转账 100
3. 提交后查看结果
4. 再开一个事务，转账 200，然后 `ROLLBACK`，看数据有没有变
5. 查看 `@@autocommit` 的值

参考：

```sql
-- 1.
CREATE TABLE IF NOT EXISTS account (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    balance DECIMAL(10,2)
);

INSERT INTO account VALUES (1, '张三', 1000.00), (2, '李四', 500.00);

-- 2.
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;

-- 3.
COMMIT;
SELECT * FROM account;   -- 张三 900，李四 600

-- 4.
START TRANSACTION;
UPDATE account SET balance = balance - 200 WHERE id = 1;
UPDATE account SET balance = balance + 200 WHERE id = 2;
SELECT * FROM account;   -- 能看到变化（700 / 800），但还没提交
ROLLBACK;
SELECT * FROM account;   -- 回到 900 / 600，没变

-- 5.
SELECT @@autocommit;     -- 默认 1
```

---

## 十一、本节总结

- 事务 = 一组**要么全成功、要么全失败**的操作
- 三个命令：`START TRANSACTION` / `COMMIT` / `ROLLBACK`
- 转账是经典场景
- MySQL 默认自动提交，开了事务就手动控制
- DML 可回滚，DDL 不可回滚
